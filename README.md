# Волшебные шары

Мобильный сайт-анонс новогодней ночи. Гость читает обращение Деда Мороза,
выбирает один из пяти шаров, шар раскрывается — и гость узнаёт тему, в которой
ему нужно упаковать и вручить подарки. Выбранный шар закрепляется за гостем и
больше не открывается другим.

## Файлы

| Файл | Что это |
| --- | --- |
| `index.html` | весь сайт: разметка, стили, анимация, логика |
| `cards.html` | просмотр всех пяти карточек тем сразу, без выбора шаров |
| `assets/` | Дед Мороз, новогодний декор и пять исходных иллюстраций тем |
| `server.js` | маленький сервер: отдаёт страницу и помнит, какие шары заняты |
| `package.json` | команда запуска для хостинга |
| `railway.json` | настройки публикации на Railway |
| `data/state.json` | создаётся автоматически при первом запуске |

Шары по-прежнему нарисованы векторно внутри страницы. Хвоя на кромках секций,
бант и фигура Деда Мороза — растровые файлы в `assets/` (`.webp`).

## Запуск

Нужен Node.js 18 или новее.

```bash
node server.js
```

Откройте `http://localhost:3000`. Порт меняется так:

```bash
PORT=8080 node server.js
```

Состояние шаров лежит в `data/state.json` и сохраняется при перезапуске.

## Как проверить, что защита работает

1. Откройте сайт на телефоне, выберите шар и подтвердите.
2. Откройте тот же адрес в другом браузере или в режиме инкогнито — выбранный
   шар будет серым с подписью «этот шар уже выбрали».
3. Вернитесь в первый браузер — ваш шар подсвечен и подписан «ваш шар»,
   при повторном открытии сайта ваша карточка показывается сама.

Занятость шаров хранится на сервере, а «кто чей шар забрал» — по метке в
браузере гостя. Два гостя не могут получить один шар: сервер отвечает отказом
тому, кто нажал вторым.

## Что можно менять без программиста

**Дата и место.** Гостям они известны, поэтому в hero сейчас стоит строка
«Дата и место вы уже знаете» с подписью «вопросы — к Яникусу». Если захотите
напечатать дату и адрес, найдите в `index.html` строку с `id="eventLine"`
и замените текст:

```html
<p class="hero__date" id="eventLine">31 декабря, 22:00<small>ул. Лесная, 8</small></p>
```

**Тексты шаров.** В начале скрипта в `index.html` есть массив `THEMES` — пять
объектов с полями `name`, `labelA`, `a`, `b`. Правьте текст в кавычках, порядок
шаров менять не нужно.

**Обращение и подпись.** Обычный текст в блоках 1, 2 и 4 — правится прямо в
разметке страницы.

## Публикация в интернете

Сайту нужен хостинг с Node.js — статичный хостинг не подойдёт, потому что
занятость шаров должен помнить сервер.

**Render** — бесплатный тариф без карты: создайте аккаунт, «New → Web Service»,
подключите архив с этими файлами через GitHub, команда запуска `node server.js`.

**Railway** — то же самое, бесплатный пробный период. Подробная инструкция ниже.

**Свой сервер или VPS** — скопируйте папку, запустите через `pm2 start server.js`
и поставьте nginx с HTTPS перед портом 3000.

**Яндекс Облако / VK Cloud** — если нужен российский хостинг с оплатой картой
Мир: создайте виртуальную машину с Node.js, дальше как в варианте с VPS.

Для праздника достаточно любой из первых двух схем: гостей немного, нагрузка
минимальная.

## Публикация на Railway

Проект уже подготовлен: есть `package.json`, `railway.json` и отдельный файл
`.railwayignore`. Зависимостей нет, сборка проходит мгновенно.

### Что сделать по шагам

1. Зайдите на **railway.app** и войдите через GitHub.
2. **New Project → Deploy from GitHub repo.** Если репозитория ещё нет —
   создайте пустой и загрузите в него все файлы из папки проекта, включая
   папку `assets/`. Служебные картинки-референсы и текст задания там не нужны —
   их отсекает `.railwayignore`.
3. Railway сам увидит `package.json` и выполнит `npm start`. Порт берётся из
   переменной `PORT`, которую платформа подставляет сама — настраивать нечего.
4. **Settings → Networking → Generate Domain** — получите адрес вида
   `volshebnye-shary-production.up.railway.app`. Это и есть ссылка для гостей.

### Постоянный том для выбранных шаров

Без тома файл состояния живёт внутри контейнера и пропадает при каждом
перезапуске. Чтобы выбор гостей сохранялся:

1. Откройте **Variables** и добавьте `DATA_DIR` = `/data`.
2. Откройте **Volumes → Add Volume**, точку монтирования укажите `/data`.
3. Перезапустите сервис.

Сервер устроен так, что сам подхватит том: если папка `/data` существует, файл
состояния создаётся там. Локально, без тома, данные лежат в `data/` рядом
с `server.js` — настраивать ничего не нужно.

### Проверка после публикации

- `https://ВАШ-АДРЕС/healthz` — должен вернуть `{"ok":true,...}` и путь
  к файлу состояния. Если `"ok":false`, том не смонтирован.
- Главная страница открывается, шары видны, выбор работает.
- `https://ВАШ-АДРЕС/cards.html` — служебный просмотр карточек. Поисковикам
  он закрыт заголовком `X-Robots-Tag`.

### Необязательная защита сброса

Добавьте переменную `RESET_KEY` со случайным значением. Тогда до праздника
можно освободить все шары одним запросом:

```bash
curl -X POST "https://ВАШ-АДРЕС/api/reset?key=ВАШ-КЛЮЧ"
```

Без этой переменной сброс запрещён (403), и шары освобождаются только удалением
файла состояния на томе.

## Если что-то пошло не так

**Все шары заняты до праздника.** Остановите сервер, удалите `data/state.json`,
запустите снова. Все шары снова свободны.

**Гость хочет поменять шар.** Пока шар закреплён за меткой в его браузере, он
видит только свою тему. Чтобы освободить шар, удалите его строку из
`data/state.json` при остановленном сервере.

**Сайт открылся без сервера** (например, файл `index.html` открыли напрямую).
Он продолжит работать, но занятость шаров будет храниться только в этом
браузере — другие гости ваш выбор не увидят. Для настоящей защиты нужен
запущенный `server.js`.

## Карточка темы

Карточка — это полноэкранная сцена. За ней лежит сильно размытая и затемнённая
иллюстрация самой темы, а поверх неё — лист с текстом. Поэтому каждая тема
узнаётся с первого взгляда, хотя ни одной картинки в самой карточке нет.

### Пять визуальных языков

Каждая тема собрана заново, а не перекрашена: у неё свой цвет, шрифт и форма.

| Тема | Название на референсе | Что определяет вид |
| --- | --- | --- |
| I | полночь и золото | тёмно-синий лист с арочным верхом, золотой ромб на арке |
| II | пергамент и компас | кремовый лист с рваным краем и точечной рамкой |
| III | обсидиан и неон | чёрный лист с золотыми уголками и мерцающими звёздами |
| IV | селадон и медь | светло-зелёная бумага с тонкой двойной рамкой |
| V | бархат и платок | бордовый лист с орнаментальной каймой внизу |

Стили заданы через переменные на `data-theme`. В `index.html` значение
подставляет скрипт (`themeEl.dataset.theme = t.id`), в `cards.html` оно
прописано в разметке каждой карточки.

### Как устроен лист

- **Сцена** — `.theme__bg`: та же иллюстрация темы, размытая на 22–30 px и
  притемнённая. фон меняется вместе с темой.
- **Лист** — `.theme__paper`: цвет, радиус углов и рамка берутся из темы.
  Внутренняя рамка — псевдоэлемент `::before`, чтобы не прокручивалась с текстом.
- **Заголовок и орнамент** — у каждой темы свой орнамент: ромб с линиями,
  компас, квадраты, листья, цветок.
- **Блоки «упаковка» и «исполнение»** — разделены тонкой линией.
- **Подвал** — кнопка в цвете темы и подсказка.

На телефоне карточка занимает весь экран, а пустое место остаётся между
примечанием и кнопкой — как в макете. На экранах шире 720 px карточка
становится окном по центру.

### Что менять осторожно

Рваный край темы II — это `clip-path` с сотней точек в процентах. Если менять
высоту листа настолько сильно, что пропорции изменятся в разы, край может
поехать; в остальных случаях он растягивается вместе с листом.

## Просмотр карточек тем

Чтобы увидеть все пять карточек сразу, не выбирая шары, откройте `cards.html` —
это отдельная страница-просмотр. Запускать сервер для неё не нужно: вся
графика нарисована стилями внутри файла, внешних картинок в нём нет.

Если сервер уже запущен, та же страница доступна по адресу
`http://localhost:3000/cards.html`.

Карточки в просмотре выровнены по высоте: если текст одной темы короче,
примечание всё равно стоит внизу, а кнопки всех пяти карточек оказываются на
одной линии.

**Важно:** `cards.html` — снимок. Он не читает `index.html` и не обновляется
сам. Если вы поменяете текст темы или оформление карточки, попросите собрать
просмотр заново.

## Иллюстрации

В папке `assets/` лежит Дед Мороз и пять исходных картинок тем:

| Файл | Где появляется |
| --- | --- |
| `theme-tale.jpg` | исходная иллюстрация «Любимая русская сказка» |
| `theme-pirate.jpg` | исходная иллюстрация «Пиратский клад» |
| `theme-future.jpg` | исходная иллюстрация «Подарок из будущего» |
| `theme-forest.jpg` | исходная иллюстрация «Подарок из леса» |
| `theme-rus.jpg` | исходная иллюстрация «Русский подарок» |
| `fir-top.webp` | ветки хвои, свисающие сверху: главный экран и гирлянда на кремовой карточке |
| `fir-bottom.webp` | те же ветки снизу: низ главного экрана и подвал |
| `fir-branches.webp` | ветки с прозрачным фоном под фигурой Деда Мороза |
| `lamp-top-1..3.webp` | три группы лампочек верхней хвои — слои мигания |
| `lamp-bot-1..3.webp` | три группы лампочек нижней хвои — слои мигания |
| `bow.webp` | атласный бант на кремовой карточке «Как это работает» |
| `santa.webp` | Дед Мороз в финальном блоке, с прозрачным фоном |

Пять `theme-*.jpg` теперь работают дважды: они подставляются размытым фоном за
карточкой своей темы в `index.html` и показаны крупно в просмотре `cards.html`.
Поле `img` в массиве `THEMES` задаёт путь к файлу.

Дед Мороз — 760 × 928 с прозрачным фоном. `fir-top` и `fir-bottom` — 1400 × 788
(один и тот же кадр, `fir-bottom` повёрнут на 180°). `fir-branches` — 1000 × 484,
`bow` — 620 × 557. Хвоя подставляется как `background-image` с маской
`linear-gradient`, поэтому кромка полосы растворяется в фоне страницы, а не
обрезается по линии.

Слои мигания `lamp-*.webp` — 700 × 394, чёрный кадр с янтарным ореолом вокруг
каждой лампочки, по 1.2–1.6 КБ. В CSS они лежат поверх фотографии с тем же
`cover` и включаются через `mix-blend-mode: screen`: чёрное исчезает, остаётся
только добавленный свет. Поэтому ореол садится ровно в лампочку на любой
ширине экрана. Три слоя — три группы ламп с периодами 5.2 / 6.9 / 8.1 с,
гирлянда переливается волной. При `prefers-reduced-motion` анимация
отключается, огоньки горят ровно.

## Новогодний декор

Пустое место сверху и снизу страницы занято декором в духе бумажного
приглашения: провисающая гирлянда с лампочками и ветви ели по углам в начале,
плотная «подушка» из хвои с огоньками и шарами в конце. Кремовая карточка
«Как это работает» тоже начинается с хвойной полосы и красного банта.

Как это устроено:

- Один скрытый SVG-спрайт (`class="deco-sprite"`) хранит пять вариантов
  еловых ветвей (`#br1`…`#br5`) и градиенты для шаров и лампочек. Ветви
  переиспользуются поворотами и отражением — поэтому декор почти не
  увеличивает вес файла.
- Пять слоёв `class="deco deco--…"` расставлены абсолютно и не ловят нажатия
  (`pointer-events:none`). Текст всегда выше них по z-index, поэтому декор не
  перекрывает ни одну надпись и не мешает выбирать шары.
- Верхний слой героя — `deco--top`, нижний — `deco--base`; подвешенные шары
  перед финалом — `deco--hang`, нижняя «подушка» финала — `deco--floor`.

Чтобы сделать декор гуще или реже, поменяйте `height` у нужного слоя в блоке
стилей (`190px`, `210px`, `250px`) и отступы блоков: `padding` у `.hero` и
`.final`. На экранах уже 340 px срабатывает отдельное правило — декор там
ниже.

Лампочки на верхней гирлянде зажигаются по очереди — медленной волной слева
направо. Это чистый CSS: девять пар кругов обёрнуты в `g.deco-lamp` с номером
в `--i`, анимация `lampPulse` сдвигает задержку на `0.7s` для каждой следующей.
Если системная настройка «уменьшить движение» включена, декор остаётся на
месте, лампочки горят ровно и анимация не запускается.

## Особенности реализации

- Анимация раскрытия — единственная крупная на сайте: свечение, трещины,
  вспышка и осколки, затем карточка темы появляется на экране. Около 1,2 секунды.
- При системной настройке «уменьшить движение» анимация сокращается, вспышка и
  осколки не показываются.
- Шары подписаны только после выбора: до этого гость не знает, какая тема
  внутри.
- Вёрстка рассчитана на 390 × 844 и работает от 320 px.
- Пустых полос сверху и снизу нет: их занимает декор, а отступы текста
  подобраны так, чтобы надписи оставались в безопасной зоне на экранах
  iPhone с «челкой».
- Шрифты подключены с Google Fonts; при их недоступности подставляются Georgia
  и системный гротеск, вёрстка не ломается.

## Проверено

Что проверено перед сдачей:

- Все пять карточек в браузере: мобильный 390×844 и десктоп 1440×900.
- Сводная страница `cards.html` на обоих размерах, без горизонтальной прокрутки.
- Сервер: `/`, `/healthz`, `/api/state`, `/api/pick`, `/cards.html` и картинки
  из `assets/` отдаются с кодом 200 и правильными типами.
- Выбор шара: повторный выбор тем же гостем возвращает уже занятый шар;
  второй гость на тот же шар получает 409; файл состояния пишется на диск.
- Переопределение `DATA_DIR`: зная точку монтирования, сервер создаёт файл
  состояния в томе, а не в папке проекта.

Что осталось за пределами песочницы: проверка на реальном телефоне и после
публикации (адрес Railway и HTTPS). Также не проверена работа под настоящей
нагрузкой — гостей немного, это не требуется.
